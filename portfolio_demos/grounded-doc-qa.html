The problem

A chatbot that returns text is easy. Knowing when it’s wrong is the job.

Most RAG demos prove a language model can produce fluent prose next to some retrieved chunks. They don’t show whether the right chunks were retrieved, whether the answer is faithful to them, or what happens when the corpus simply doesn’t contain the answer.

This project treats the evaluation harness as the product and the chat UI as the wrapper. Every retrieval decision — chunking strategy, top-k, reranker on or off, fusion weights — is a named, serialisable config, and the harness scores a matrix of those configs against a golden set so you can point at the number that changed.

What it does

Six stages, each independently measured

The pipeline is ordered, and every stage writes structured logs — parser used, OCR yes/no, chunks produced, fusion inputs, rerank scores — so a failure can be localised to one stage instead of blamed on “the model”.

01

Ingest a messy corpus with lineage

Loader dispatches on file type; OCR fallback fires when extracted text density drops below threshold. Repeated headers and footers stripped, table text and page numbers preserved. Re-running ingestion on an unchanged corpus inserts zero rows; a changed file supersedes its chunks without deleting history.

PyMuPDF · python-docx · Tesseract · documents / chunks / ingestion_runs

02

Two chunking strategies behind one interface

fixed_token at 512 / 64 overlap, and structural that respects headings and sections. Selectable by config because the eval harness needs to compare them.

strategy recorded per chunk row

03

Hybrid retrieval with reciprocal rank fusion

pgvector cosine search over an HNSW index, Postgres full-text search on tsvector, fused with RRF. Keyword recall catches the exact-term queries that dense retrieval misses.

vector + BM25-style FTS → RRF

04

Cross-encoder reranking

ms-marco-MiniLM re-scores the top-k fused candidates. k values configurable; reranker toggleable — both are axes in the evaluation matrix.

sentence-transformers CrossEncoder

05

Grounded answer or an honest refusal

The generation prompt must cite. The response payload carries answer, citations[] with filename, page, chunk id and score, and the full retrieved_context[]. If nothing clears the score floor, the system says it cannot answer from the corpus — it does not guess.

Ollama local · OpenAI / Anthropic cloud mode

06

Evaluate the whole matrix

2 chunking strategies × reranker on/off, minimum four runs, persisted to eval_runs with a config hash, per-question results and aggregates. make eval prints a comparison table and the Streamlit page charts it.

Ragas · hit-rate@k · MRR · refusal accuracy

What it measures

The golden set carries the hard cases on purpose

40–50 questions, each with expected answer facts and the expected source document and page. It deliberately includes an answer spanning two documents, an answer only in a scanned doc, an answer only in v2 of a near-duplicate pair, and five unanswerable questions.

hit-rate@k
Did the expected source chunk appear in the top k retrieved, before generation ever runs.
MRR
How high the correct chunk ranked — rewards getting the right context to the top, not just into the window.
context precision / recall
Ragas: how much of the retrieved context was relevant, and how much of the relevant context was retrieved.
faithfulness
Ragas: whether the answer’s claims are entailed by the retrieved context — the direct measure of hallucination.
answer relevancy
Ragas: whether the answer actually addresses the question asked.
refusal accuracy
On the five unanswerable questions, did the system correctly decline instead of guessing.

Run it

Clean clone to eval table in four commands

No manual setup beyond copying .env.example. Local mode uses sentence-transformers for embeddings and Ollama for generation — no keys, no paid calls. A cloud mode flips to OpenAI or Anthropic by env var.

$ cp .env.example .env
$ docker compose up # Postgres + pgvector, app, Ollama profile
$ make fetch-corpus # download public-domain docs per corpus/manifest.yaml
$ make ingest # idempotent — run twice, get identical chunk counts
$ make eval # runs the 4-config matrix, prints the comparison table
$ make ui # Streamlit: Chat + Evaluation pages
